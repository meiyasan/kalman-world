Detailed Description

Plans horizon commands ahead at every step, honouring limits on the command while it plans, applies the first one, and plans again.

The plan minimises, over the commands u_0 ... u_{N-1},

sum_{k=1}^{N-1} e_k^T Qcost e_k + e_N^T Pf e_N + sum_{k=0}^{N-1} u_k^T Rcost u_k
e_k = x_k - x_ref, x_{k+1} = f(x_k, u_k, t_k), x_0 = the estimate

subject to uMin <= u_k <= uMax and, when a rate limit is given, |u_k - u_{k-1}| <= duMax (with u_{-1} the command applied last).

Where it sits beside the other controllers: Controllers::LQR is one gain from one linearisation, with no notion of a limit; Controllers::MPPI replans by rolling random command sequences through f. This one replans deterministically, and the limits are constraints of the plan, not a clip applied after it.

  • The prediction model is the model's own f. A model of matrices is predicted exactly (F, B). A nonlinear one is linearised along the previous plan: its state Jacobian from Model::Jacobian(), its command Jacobian differenced towards the inside of the limits (an f that clips its command has no slope outside them). nIterations such passes are made per step, each around the plan the last one found; one is enough when the plan is warm, which it is: the plan of the previous step, shifted by one, starts the next.
  • The terminal cost Pf is by default the solution of the discrete Riccati equation at the set point (Algebra::SolveDARE), so that with no limit in the way the first command is the LQR command, whatever the horizon. Where that equation has no solution it falls back to Qcost.
  • The quadratic programme is solved in its dual by Hildreth's method (coordinate ascent on the multipliers of the limits): no dependency, no general factorisation (the one inverse is of the plan's Hessian, which is symmetric positive definite), and the same answer for the same input. With no limit active it is one linear solve.

The plan it made and the states it predicts for it are kept: Plan(), Predicted().
