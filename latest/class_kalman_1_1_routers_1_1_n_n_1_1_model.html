Detailed Description

A learned policy: features in, mode probabilities out.

The C++ counterpart of modules/framework/routers/nn/, and it keeps that package's division of labour exactly:

  • The router (Kalman::Routers::Neural) owns feature extraction and normalisation — the NIS window, the front-padding, the standardisation.
  • The model owns the architecture and the forward pass.

That split is what makes the architecture swappable without touching the router, and it is why this contract is one method wide. Python states it as "any callable ``model(features) → probs`` works"; here it is:

Vector probabilities = model(features);

Training lives in Python

Python's models carry build() and fit() alongside __call__, because that is where training belongs — the data loaders, the optimiser, the notebooks. This contract has no training hooks, deliberately: a model here is always already trained. Two ways to get one:

  • Kalman::Routers::NN::Onnx — execute a policy exported from any of the Python architectures (MLP, CNN, LSTM, Transformer). Needs ONNX Runtime.
  • Kalman::Routers::NN::MLP — evaluate a two-layer tanh MLP directly from its weights. Needs nothing at all, which is what keeps the routing layer usable in a build with no optional dependencies whatsoever.

Implement this interface for anything else; the router will not notice.

Forward pass.

Parameters
featuresstandardised feature vector of length NInputs().
Returns
one probability per mode, length NOutputs().

Implementations return probabilities, not logits: the softmax belongs to the architecture, and putting it here rather than in the router is what lets a model whose head is already a softmax — an exported ONNX graph, say — satisfy the same contract without a second one applied on top.

Implemented in Kalman::Routers::NN::MLP, Kalman::Routers::NN::Onnx, and Kalman::Routers::NN::Torch.
