Detailed Description

A model written to one file, and read back.

A .kw file ("Kalman World") is one archive (Kalman::IO::Archive, a zip) that holds everything a model file is made of, so its parts cannot be separated or mixed with another model's:

  • model.json: the readable part. What the model is, its settings, and a spec in the form the JSON API takes (kalman.api, kalman-serve);
  • tables/<name>.f64: what does not belong in text, raw little-endian float64, described (shape, samples) in model.json.

The same code writes any model, through the Kalman::Model interface. What the file can hold depends on what the model is made of (Model::Structure()):

Structure File (kind) Reads back
Matrices complete: F, H, B, L, Q, R, x0, P0, fs (or A and Qc when stated in continuous time) anywhere
TimeVarying complete over a stated number of samples: the matrices that change, as tables anywhere
Maps reference: the registered name, its plugin, parameters, noise, initial state where the plugin is installed
any, on request linearization: the Jacobians at one state, as a Matrices model anywhere, valid near that state

model.json alone (no tables) may also be saved as plain JSON, to a path ending in .json. A file with tables is refused that way: its JSON would not be the whole model.

Settings: name.kw.json
A .kw file holds the model with the settings it was written with. To move away from them without touching it, a settings file sits beside it under the same name plus .json: car.kw and car.kw.json. It holds only what changes, among the sample rate, the named parameters, the noise (Q, R) and the initial state (x0, P0); what it does not mention keeps the value of the .kw. Open() applies it. It is not a model: it cannot change the matrices or the code, a key it does not know is refused, and it carries the name of the model it was written for, so the settings of another model are refused instead of applied.
