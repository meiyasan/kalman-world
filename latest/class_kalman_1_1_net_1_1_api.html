Detailed Description

The JSON verbs of the Python facade kalman.api, for models that live in C++.

One entry point, Call(): a verb name, its arguments as a JSON object, the caller's token, and a JSON answer – the same verb names, argument names and answer shapes as modules/api/__init__.py, so a client written against the Python REST or MCP server talks to this one unchanged.

What it serves:

  • every model Kalman::Factory knows: libKalmanApps (loaded at start when it is found) and the plugins loaded since, by their registered names ({"base": "constant-velocity"});
  • authored specs of the shared registry whose base is matrices or continuous, and specs given inline with those bases;
  • the registry itself, read from the same SQLite file as Python ($KALMAN_STATE_DIR/registry.sqlite): authored models, plugins, sources, events, the revocation list.

What it does not: models written in Python (their code is in the Python process), and the verbs that need Python libraries (plots, providers, OSSE, control, authoring). Those answer 501 and name the Python server.

verb scope arguments
catalog read –
describe read name
models read –
sources read –
describe_source read name
events read since, limit

native read –
diagnostics read run_id
whoami (none) –
sample send_measurement spec, duration, seed, process_noise, measurement_noise
run_filter send_measurement spec, data or source (+query), smooth
forecast send_measurement spec, x0, P0, steps
load_plugin load_plugins name

Calls are serialised: one runs at a time per Api, so the servers may call it from any thread.
