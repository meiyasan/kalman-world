Detailed Description

Is the filter consistent? — computed post-hoc from a finished run.

Separated from Kalman::Filter for the same reason as modules/framework/diagnostics.py: these are questions asked about a run, not steps of one. Nothing here feeds back into the estimate, and everything is derived from the stored prior/posterior/innovation logs plus the model's H and R, so a diagnostic can be added without touching an engine.

The two that matter:

  • NIS — normalised innovation squared. Needs no truth, so it works on real data. Averages the number of measurement channels for a consistent filter; persistently larger means the filter trusts the model too much (Q too small), persistently smaller means Q is too large.
  • NEES — normalised estimation error squared. Needs truth, so it is a simulation tool. Averages the state dimension for a consistent filter.

A filter whose estimates look right on a plot but whose NIS sits at 5 is reporting error bars that are a factor of two too small, and that is invisible in the trajectory alone. Kalman::Filter forwards to this class, so filter.MeanNIS() is the short way in.
