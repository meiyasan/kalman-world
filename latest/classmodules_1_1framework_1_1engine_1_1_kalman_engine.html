Detailed Description

Abstract Kalman **engine** base — the inference algorithm (HOW), one step at a time.

**Core quantities** (passed to every method as arguments, never stored here):

- ``x`` (ψ in math notation) — state vector, shape ``(n, 1)``.  The hidden
  quantities the filter estimates (e.g. position, velocity, acceleration).
- ``P`` — state-error **covariance matrix**, shape ``(n, n)``.  Encodes uncertainty
  in the current estimate: ``P = E[(ψ - ψ̂)(ψ - ψ̂)ᵀ]``.  Diagonal entries are
  per-state variances; off-diagonals capture cross-correlations.
- ``F`` — **state-transition matrix**, shape ``(n, n)``.  The discrete-time linear
  map ``ψ_{k+1} = F ψ_k`` (no noise); equals ``exp(A Δt)`` for a continuous system
  with dynamics matrix ``A``.  For nonlinear models ``F = ∂f/∂ψ`` (Jacobian).
- ``Q`` — process-noise covariance, ``(n, n)``; ``R`` — measurement-noise
  covariance, ``(m, m)``.  Larger ``Q`` → trust model less; larger ``R`` → trust
  sensor less.

**Two layers**:

- ``_propagate`` / ``_measure`` — pure model evaluation for one step: the
  nonlinear map and its Jacobian (``f``/``F`` for the state transition,
  ``h``/``H`` for the observation). This is the *only* part that differs
  between algorithms, so it's the hook each engine overrides
  (:class:`LinearKalmanEngine` / :class:`ExtendedKalmanEngine`).
- ``_predict`` / ``_update`` — the **shared** covariance machinery: propagate/
  update ``P``, inject process noise ``Q``, compute the gain ``K``, apply the
  masked Joseph-form correction. Identical for every Jacobian-based engine;
  it calls ``_propagate``/``_measure`` to get the algorithm-specific piece.

UKF/PF have no single Jacobian (sigma points / particles instead), so they
skip the hooks and override ``_predict``/``_update`` wholesale.

The engine *knows the model* (it calls ``model.F/H`` or ``model.f/h``) but owns no
run state and nothing about workflow — that is the ``KalmanFilter``'s job.

**Whole-pass engines.** For some algorithms one predict/update step is not the
whole story: a combinatorial track finder branches, prunes and arbitrates across a
whole event, and no per-step loop over single measurements describes it. Such an
engine sets ``OWNS_PASS = True`` and implements :meth:`forward` / :meth:`backward`;
``KalmanFilter`` then hands it the data and turns whatever it returns into records,
instead of running its own loop. The algorithm still lives in the engine and the
workflow still lives in the filter — the split just falls in a different place.
Objects returned by such a ``forward`` must expose ``to_record(model, flavor)``.

Whether the process noise goes *through* ``model.f`` (passed as ``w``)
instead of being added after it.

A model that declares its noise coupling ``L`` (a matrix given to the
constructor, or an ``L`` method of its own) has said the noise is added,
as ``L w``; that is what the extended engine does, and every engine must
agree with it. Many models take ``w`` in ``f``'s signature and ignore
it: reading the signature alone made the sigma-point and particle
engines drop their process noise altogether. So the noise goes through
``f`` only when ``f`` takes ``w``, the model declares no coupling, *and*
``f`` responds to ``w`` when tried (:meth:`_responds_to_noise`).

Prediction step → ``(xk, Pk, F)``.

Propagates the prior belief one step forward using the motion model:

.. code-block:: text

    xk  = F · x  + B · u          (mean prediction)
    Pk  = F · P · Fᵀ + Q          (covariance prediction)

where ``F`` is the state-transition matrix (``∂f/∂x`` for nonlinear models)
and ``Q`` is the process-noise covariance.  Returns the predicted mean
``xk``, the predicted covariance ``Pk``, and the transition matrix
``F`` used (needed later by the RTS smoother).

staticprotected 
Whether ``model.f`` (``which="f"``) or ``model.h`` actually changes when
handed a noise sample.

``f(x, u, w, t)`` and ``h(x, v, t)`` are the contract's signatures, so a
model has ``w`` and ``v`` in them whether or not it uses them. One that
ignores the argument and declares no coupling would lose its ``Q`` (or
``R``) in the sigma-point and particle engines, which hand the noise to
the map: the unscented filter then trusted its sensor completely. So the
map is tried once, at the initial state, with and without a sample; a map
that does not move takes its noise added (``L = I``, ``M = I``), as the
extended engine does. The answer is kept on the model.

135 handed a noise sample.
136

138 model has ``w`` and ``v`` in them whether or not it uses them. One that
139 ignores the argument and declares no coupling would lose its ``Q`` (or

143 that does not move takes its noise added (``L = I``, ``M = I``), as the
144 extended engine does. The answer is kept on the model.
145 """
146 cache = model.__dict__.setdefault("_noise_response", {})
147 if which in cache:
148 return cache[which]
149 answer = True # if the map cannot be tried, believe its signature
150 try:
151 n, m = int(model.n), int(model.m)
152 x0 = getattr(model, "x0", None)
153 x = np.zeros((n, 1)) if x0 is None else np.asarray(x0, dtype=float).reshape(n, 1)
154 t = getattr(model, "t0", None)
155 t = 0.0 if t is None else float(t)
156 if which == "f":

158 u = np.zeros((int(model.l), 1)) if int(model.l) > 0 else None
159 sample = np.linspace(0.5, 1.0, q).reshape(q, 1)
160 quiet = np.asarray(model.f(x, u=u, w=np.zeros((q, 1)), t=t), dtype=float)

162 else:

164 sample = np.linspace(0.5, 1.0, r).reshape(r, 1)
165 quiet = np.asarray(model.h(x, v=np.zeros((r, 1)), t=t), dtype=float)
166 moved = np.asarray(model.h(x, v=sample, t=t), dtype=float)
167 if np.all(np.isfinite(quiet)) and np.all(np.isfinite(moved)):

One reverse RTS (Rauch–Tung–Striebel) step → ``(x_s, P_s)``.

Given the forward-pass posterior at step ``k`` and the already-smoothed estimate
at step ``k+1``, computes the smoothed estimate at step ``k``:

.. code-block:: text

    C   = P_k · Fᵀ · P_{k+1|k}⁻¹    (smoother gain)
    x_s = x_k + C · (x_s_{k+1} − x_{k+1|k})
    P_s = P_k + C · (P_s_{k+1} − P_{k+1|k}) · Cᵀ

where ``F_k`` is the transition matrix stored during the forward pass at step ``k``.

Update step → ``(x, P)``.  Missing channels (NaN in ``z``) are skipped.

Fuses the predicted belief with the measurement using the standard equations:

.. code-block:: text

    S  = H · P · Hᵀ + R              (innovation covariance)
    K  = P · Hᵀ · S⁻¹               (Kalman gain)
    x  = x + K · (z − H · x)        (corrected mean, overwrites prior)
    P  = (I − KH) · P · (I − KH)ᵀ + K · R · Kᵀ   (Joseph form, overwrites prior)

The Joseph form is used for ``P`` to preserve symmetry and positive-definiteness
even under numerical round-off.

223
224 Fuses the predicted belief with the measurement using the standard equations:
225
226 .. code-block:: text
227
228 S = H · P · Hᵀ + R (innovation covariance)
229 K = P · Hᵀ · S⁻¹ (Kalman gain)
230 x = x + K · (z − H · x) (corrected mean, overwrites prior)
231 P = (I − KH) · P · (I − KH)ᵀ + K · R · Kᵀ (Joseph form, overwrites prior)
232
233 The Joseph form is used for ``P`` to preserve symmetry and positive-definiteness
234 even under numerical round-off.
235 """

237 keep = ~np.isnan(z).ravel()

239 return x, P
240
241 zk, H = self._measure(model, x, t)
242 H = np.asarray(H, dtype=float)
243 R = np.asarray(model.R(t=t), dtype=float)
244 # Residual against the true (possibly nonlinear) h(x), NOT H @ x -- NaN
245 # propagates automatically wherever z is missing, matching `keep`.
246 yk = z.reshape(-1) - np.asarray(zk, dtype=float).reshape(-1)
247

252 xk = np.empty(n, dtype=np.float64)
253 Pk = np.empty((n, n), dtype=np.float64)
254 lib.kf_update_residual(
255 n, H.shape[0],
256 dptr(as_contiguous(H)), dptr(as_contiguous(np.asarray(x, dtype=float).reshape(-1))),
257 dptr(as_contiguous(P)),
258 dptr(as_contiguous(yk)), dptr(as_contiguous(R)),
259 dptr(xk), dptr(Pk),
260 )

266
267 S = R + H @ P @ H.T
