libKalman — the Kalman framework in C++

The framework core in C++: a standalone library with no required dependency. Not ROOT, not Eigen, not Torch — just a C++20 compiler.

#include <Kalman/Kalman.h>
class MyModel : public Kalman::Model { ... }; // your system
MyModel model;
Kalman::Filters::KF filter(&model);
auto record = filter.Forward(measurements);
printf("mean NIS = %.3f\n", filter.MeanNIS());

The three roles

The dependency arrows point one way only — Filter → Engine → Model:

Role Question Class
Model WHAT is the system? Kalman::Model
Engine HOW to infer? Kalman::Engine (Kalman::Engines::Linear, Extended, Unscented, Particle, Ensemble)
Filter WHEN does it run? Kalman::Filter (Kalman::Filters::KF, EKF, UKF, PF, EnKF); Kalman::Filters::IKF, Kalman::Filters::CKF
Controller WHAT to command? Kalman::Controller (Kalman::Controllers::Proportional, PID, LQR, MPPI, Boost, AdaptiveQR)

The decision layer

Kalman::Filters::IKF runs several models at once and carries a probability on each; a Kalman::Routers::Router owns that probability update and is the only pluggable part of the step. Kalman::Routers::Bayesian is the classical rule, Kalman::Routers::Threshold a NIS-based one, Kalman::Routers::Hybrid a blend, and Kalman::Routers::Neural executes a policy trained in the Python framework and exported to ONNX — the trained policy, not a language binding, being what crosses between the two implementations.

Supporting types: Kalman::Record (one pass, with its covariance band), Kalman::Sampler (truth and measurements drawn from a model), Kalman::Matrix / Kalman::Vector (the small dense types), and Kalman::Utils (shared algebra).

No applications here

libKalman ships no physics. A pendulum, a drift chamber, a suspension or a power grid is an application: it subclasses Kalman::Model and lives with the domain knowledge, not in the framework. What is here is the contract those applications are written against.

Optional backends

Everything works without it. See Kalman/Config.h.

  • BLAS (KALMAN_WITH_BLAS) — matrix products at or above KALMAN_BLAS_MIN_DIM go through cblas_dgemm. Below it the hand-rolled kernel is measurably faster, so the choice is per operation.

libKalman links no AI runtime. Running a policy trained in the Python framework and exported to ONNX or TorchScript is libKalmanLearn's job: see libKalmanLearn — learned components and Kalman/Learn/Learn.h. The application models are libKalmanApps, under Kalman/Apps/.
