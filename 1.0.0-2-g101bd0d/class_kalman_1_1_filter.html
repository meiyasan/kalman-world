Detailed Description

The workflow — WHEN each step runs, and what is kept.

A filter composes a model (WHAT) with an engine (HOW) and owns the run: the current belief (x, P) and the prior / posterior / transition logs that the RTS backward pass and the consistency diagnostics need. It implements no covariance math of its own — every matrix operation happens in the engine.

MyModel model; // your system; libKalman ships no physics
Kalman::Filters::KF filter(&model);
auto forward = filter.Forward(measurements); // filtered estimate
auto smoothed = filter.Backward(); // RTS over the same run
Kalman::Filters::KF
The standard Kalman filter — a model driven by Kalman::Engines::Linear.
Definition KF.h:37

Missing data needs no special handling: a NaN channel in a measurement is skipped by the update, so a step with an entirely-NaN measurement is a pure prediction and the covariance grows accordingly.

Note
The filter does not own the model — it is passed by pointer and must outlive the filter. It does own the engine it creates for itself; an engine passed in explicitly stays the caller's.

The closed-loop forward pass: controller decides each step's command.

Once per step, before the prediction, the controller is called with the current belief, the time and the previous innovation, exactly as KalmanFilter.forward(zk, uk=controller) does in Python. The commands are kept in Controls(); the controller keeps its own cost log.

◆ NIS()

std::vector< double > Kalman::Filter::NIS ( ) const

Normalised Innovation Squared, nu^T S^-1 nu per step.

Needs no truth. For a consistent filter it averages the number of measurement channels; persistently larger means the filter trusts the model too much (Q too small), persistently smaller means Q is too big. Steps with no measurement at all are reported as NaN so they stay out of averages instead of biasing them toward zero.
