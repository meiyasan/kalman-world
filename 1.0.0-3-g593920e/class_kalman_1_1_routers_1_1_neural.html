Detailed Description

Delegates the mode decision to a learned policy.

Mirrors modules/framework/routers/neural.py, including the division of labour that file states in its first two lines:

  • This class owns feature extraction and normalisation — the NIS window, the front-padding, the standardisation learned at training time.
  • The model owns the architecture and the forward pass — see Kalman::Routers::NN::Model.
Kalman::Routers::NN::Onnx policy("router.onnx"); // or NN::MLP, or your own
Kalman::Routers::Neural router(&policy, 5);
Kalman::Filters::IKF ikf(models, Pi, &router);

Note
There is no ONNX in this header, and none in its implementation. The runtime is confined to Kalman::Routers::NN::Onnx, so this router works in a build with no optional dependencies at all — with NN::MLP, or with any model you implement. That is what "optional" has to mean to be worth anything: not a class that throws when the dependency is missing, but a layer that still functions without it.

Features

The last window NIS rows, front-padded with 1.0 (the chi2(1) mean) and flattened row-major to M × window, then standardised. The layout is fixed by routers/neural.py and must match bit for bit — a mismatch does not fail, it quietly returns a meaningless probability vector.

Standardisation is applied only when SetNormalisation() has been given matching-length vectors. NeuralRouter.export_onnx() bakes it into the graph by default, in which case there is nothing to set here and nothing to get out of step.

Note
Until a model is attached, Route() falls back to the classical Bayesian update rather than failing. Check IsReady() if you need to know which one you are getting.
