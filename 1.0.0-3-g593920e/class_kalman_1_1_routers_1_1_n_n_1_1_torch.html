Detailed Description

Executes a TorchScript policy through libTorch.

The closest C++ mirror of modules/framework/routers/nn/, whose four architectures are all torch.nn modules: this runs the very same module, traced to TorchScript, with no conversion step in between.

router = NeuralRouter(model=LSTM(hidden=32), window=5)
ikf.fit(training_zk, labels)
router.export_torchscript("router.pt")
Kalman::Routers::NN::Torch policy("router.pt");
Kalman::Routers::Neural router(&policy, 5);

Torch or ONNX?

Both are optional, both satisfy Kalman::Routers::NN::Model, and the router cannot tell them apart. They differ in what they cost you:

TorchScript (this) ONNX (Kalman::Routers::NN::Onnx)
Fidelity the same module, traced a converted graph
Coverage anything torch.jit.trace accepts anything the exporter supports
Runtime libTorch (~2 GB) ONNX Runtime (~10 MB)
Reach Torch only any ONNX runtime, any language

Prefer TorchScript when the architecture is exotic enough that the ONNX exporter mangles it, or when libTorch is linked anyway — root-plus' Tensor component already carries it. Prefer ONNX for deployment, where the runtime is a tenth of the size and does not tie the binary to a Torch version.

Note
ONNX and libTorch are independent options. Neither is required, both may be present, and Kalman::Routers::NN::MLP needs neither — so the routing layer works in a build with no optional dependency at all.

Implementations return probabilities, not logits: the softmax belongs to the architecture, and putting it here rather than in the router is what lets a model whose head is already a softmax — an exported ONNX graph, say — satisfy the same contract without a second one applied on top.
