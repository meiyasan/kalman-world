1"""kalman/framework/native — the C++ core's kernels under the Python engines.
2
3The Python engines evaluate the *model* themselves — ``f`` at the sigma points,
4``F/H/Q/R`` at the current point, ``h`` at every particle — and hand the arrays to
5``libKalman`` for the *step*: the covariance prediction, the NaN-masked
6Joseph update, a whole linear pass, the RTS sweep, the sigma-point moments,
7particle weights and resampling, NIS and NEES. One crossing per step with
8arrays, never a callback per point. Those kernels are the same code as the C++
9engines a ROOT+ program runs (``Kalman::Filter``, ``Engine::Smooth``,
10``Utils::Correct`` ...), so a Python model here and a C++ model there run one
11implementation of the arithmetic.
12
13Exposes ``HAS_C_ACCEL`` and, when the library was found (see ``core.py`` for
14where it is looked for), ``ffi``/``lib`` plus ``dptr``/``iptr`` helpers to get raw
15pointers from contiguous numpy arrays. Every call site in the engines guards on
16``HAS_C_ACCEL`` and falls back to the pure-Python path when the library is not
17built -- the C++ path is faster and shared, never load-bearing for correctness.
18
19This module used to compile its own C copy of these kernels (``kalman.c``); a
20second implementation of a Kalman step was a second place for it to be wrong.
21"""
