Detailed Description

Several models side by side, each with its own state.

The parts evolve independently, so the state is theirs one after the other and the motion is block-diagonal:

x = [ x1 ; x2 ; ... ] f(x) = [ f1(x1) ; f2(x2) ; ... ]
F = diag(F1, F2, ...) Q = diag(Q1, Q2, ...)

What is measured depends on the Kalman::Readout:

Stacked: z = [ h1(x1) ; h2(x2) ; ... ] R = diag(R1, R2, ...) each part brings its sensors
Summed: z = h1(x1) + h2(x2) + ... R = R1 the parts share one measurement

Summed is several signals on one channel: the lines of a spectrum, a signal and its background. The parts then have the same number of measurements, and the noise of the channel is the first part's.

The controls are the parts' one after the other. A named parameter of a part is <part>.<name> here, the part being called by its model's name (numbered from the second when two share one: osc, osc2), or by the names given. A state or measurement component keeps its name unless two parts share it; it then carries its part's in front (osc_position, osc2_position).

When every part is its matrices the composite is too, and the linear engine runs it; one part that is code makes it code. Each part linearises itself: the Jacobians are the parts' own, in blocks.

The parts are shared, not copied, and step at this model's sample rate. This is not Models::Fusion, where a second sensor reads the same state.
