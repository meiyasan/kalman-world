Detailed Description

Verifies the scoped JWTs that the Python side issues.

The tokens are those of modules/api/auth.py: HS256 over the secret in KALMAN_JWT_SECRET, with the claims sub, scopes, iat, exp, jti, and iss/aud when KALMAN_JWT_ISSUER/KALMAN_JWT_AUDIENCE are set. A token minted by python -m kalman.api.auth token or POST /token is accepted here unchanged, and a token revoked through Python is refused here, because the revocation list is read from the same registry ($KALMAN_STATE_DIR/registry.sqlite).

The rules are Python's, checked in the same order:

  • no secret configured: auth is off, every call is allowed (local use);
  • a secret configured: a token is required, its signature, exp (and nbf, iat), iss and aud must hold, it must not be revoked (401 otherwise), and it must carry the scope or admin (403 otherwise).

Issuing tokens and managing accounts (bcrypt, the htpasswd file, logins and their lockout) stay in Python: this class only verifies. Sign() exists for tests and for tools that already hold the secret.
