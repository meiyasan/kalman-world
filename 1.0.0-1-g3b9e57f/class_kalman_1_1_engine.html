Detailed Description

The algorithm — HOW to infer under uncertainty, one step at a time.

An engine is stateless. It reads a model, takes a belief (x, P) in and hands a new belief back; it never stores a run, and it knows nothing about the order in which steps are driven (that is the filter's job).

The class splits into two layers, exactly as in the Python framework:

  • Propagate() / Measure() — the only part that differs between algorithms: evaluate the dynamics and observation maps and hand back their Jacobians. Each concrete engine overrides these two.
  • Predict() / Update() / Smooth() — the covariance machinery, shared by every Jacobian-based engine: inject Q, form the gain, apply the Joseph-form correction, run one reverse RTS step. Written once, here.

Measurement update in Joseph form; NaN channels of z are skipped.

S = H P H^T + R innovation covariance
K = P H^T S^-1 Kalman gain
x = x + K (z - h(x)) corrected mean

The residual is taken against the true (possibly nonlinear) h(x) rather than H x, which is what makes the same code correct for the extended engine.

Parameters
modelthe system.
x,Pthe predicted belief.
zthe measurement; NaN marks a missing channel.
tthe time tag of this step.
[out]xOutthe corrected mean.
[out]POutthe corrected covariance.
Returns
the number of measurement channels actually used (0 when the whole measurement was missing, in which case the belief passes through unchanged — a predict-only step).

Reimplemented in Kalman::Engines::Ensemble, Kalman::Engines::Particle, and Kalman::Engines::Unscented.
